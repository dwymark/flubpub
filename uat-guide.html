1. Prerequisites & Environment Setup

All tests assume the server is running locally. Start it in a separate terminal:

uv run flubpub serve

Verify the server is healthy:

curl http://localhost:8000/health
# Expected: {"status":"ok"}

Note: All uv run flubpub commands below assume you are in the project root directory.

2. Feature 1: Markdown Image Upload Fix (Sub-Pages)

Previously, when pushing a markdown file that linked to sub-pages containing images, the sub-page images were never uploaded. URLs were rewritten to /assets/{sub-slug}/img.png but the files didn't exist on the server. This is now fixed.

2.1 Setup Test Files

Prerequisite: a real PNG image at ~/Downloads/FirstPainting.png (any valid PNG will do).

mkdir -p /tmp/flubpub-img-test/pics

# Use a real image for both main and sub-page
cp ~/Downloads/FirstPainting.png /tmp/flubpub-img-test/main-photo.png
cp ~/Downloads/FirstPainting.png /tmp/flubpub-img-test/pics/sub-photo.png

# Create a sub-page with its own image
cat > /tmp/flubpub-img-test/gallery.md <<'EOF'
# Gallery

Here is the gallery image:

![Sub Photo](pics/sub-photo.png)
EOF

# Create main page linking to the sub-page and its own image
cat > /tmp/flubpub-img-test/album.md <<'EOF'
# Photo Album

Main photo:

![Main Photo](main-photo.png)

See also the [Gallery](gallery.md) for more.
EOF

2.2 Push and Verify Sub-Page Images Upload

Step: 
cd /tmp/flubpub-img-test
uv run --project ~/projects/flubpub flubpub push album.md --title "Photo Album"
Expected output: 
Local references found:
  Images:
    ./main-photo.png
  Linked pages:
    ./gallery.md

These files will be uploaded. Continue? [y/N]
Type y and press Enter.

Expected: Should see: 
Uploaded asset: main-photo.png
Uploaded asset: sub-photo.png (for gallery)
Pushed linked page: gallery
Published: Photo Album
/photo-album/

Key verification: the line Uploaded asset: sub-photo.png (for gallery) confirms the fix. Previously this upload was missing entirely.

2.3 Verify Sub-Page Image Is Accessible

Step: Check that the sub-page image was uploaded under the sub-page's slug.
curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/assets/gallery/sub-photo.png
Expected: HTTP status 200

2.4 Verify Main Page Image Is Accessible

Step: 
curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/assets/photo-album/main-photo.png
Expected: HTTP status 200

2.5 Verify Rewritten URLs in Content

Step: 
uv run flubpub get photo-album
Expected: Content contains ![Main Photo](/assets/photo-album/main-photo.png) and [Gallery](/gallery/).

uv run flubpub get gallery
Expected: Content contains ![Sub Photo](/assets/gallery/sub-photo.png).

2.6 Verify Images Render in Browser

Step: Open http://localhost:8000/photo-album/ and http://localhost:8000/gallery/ in a browser.
Expected: Both pages render with their images visible (not broken image icons).

3. Feature 2: Color Schemes (Separated from Themes)

Color palettes are now independent of layout themes. Each theme has a default color scheme, but you can mix any color scheme with any theme.

3.1 List Available Color Schemes

Step: 
curl http://localhost:8000/api/color-schemes
Expected: JSON array: ["clean","neon","midnight","terminal","starfield","parchment"]

3.2 Push with Default Color Scheme (Unchanged Appearance)

Step: Push a page with a theme but no explicit color scheme.
echo "<p>Testing default colors</p>" > /tmp/cs-test.html
uv run flubpub push /tmp/cs-test.html --title "Hacker Default" --slug cs-hacker-default --theme hacker
Expected: Open http://localhost:8000/cs-hacker-default/. Should look identical to the pre-refactor hacker theme: black background, green monospace text, scanline overlay.

3.3 Push with Cross-Theme Color Scheme

Step: Use the hacker layout with the midnight (academic) color scheme.
uv run flubpub push /tmp/cs-test.html --title "Hacker Midnight" --slug cs-hacker-midnight --theme hacker --color-scheme midnight
Expected: Open http://localhost:8000/cs-hacker-midnight/. Should have the hacker layout (ASCII box, scanlines, monospace) but with midnight colors: navy background (#000040), light gray text (#e0e0e0), yellow headings (#ffff99).

3.4 Push with Multiple Cross-Combinations

Step 1 — Geocities layout + terminal colors: 
uv run flubpub push /tmp/cs-test.html --title "Geocities Terminal" --slug cs-geo-terminal --theme geocities --color-scheme terminal
Verify: Open in browser. Geocities layout (marquee, visitor counter, badges) with terminal colors (black bg, bright green text).

Step 2 — Academic layout + starfield colors: 
uv run flubpub push /tmp/cs-test.html --title "Academic Starfield" --slug cs-acad-starfield --theme academic --color-scheme starfield
Verify: Academic layout (minimal, serif) with starfield colors (deep blue bg, light blue text, gold headings).

3.5 Revise with Color Scheme Change

Step: 
echo "<p>Now with neon colors</p>" > /tmp/cs-test-v2.html
uv run flubpub revise cs-hacker-default /tmp/cs-test-v2.html --color-scheme neon
Expected: Revised: Hacker Default
Verify: Open http://localhost:8000/cs-hacker-default/. Should now have neon colors (dark purple bg, yellow text) with hacker layout.

3.6 Invalid Color Scheme Name

Step: 
uv run flubpub push /tmp/cs-test.html --title "Bad Scheme" --slug bad-scheme --theme default --color-scheme nonexistent
Expected: Error message containing Unknown color scheme: nonexistent.

3.7 View Page Source to Verify CSS Variables

Step: 
curl -s http://localhost:8000/cs-hacker-midnight/ | head -10
Expected: Should contain a <style>:root { --bg: #000040; --fg: #e0e0e0; ... }</style> block near the top of the <head>.

4. Feature 3: SSH Remote Push

The --remote option bypasses the HTTP API entirely, using scp + ssh to manage pages on a remote server. Requires SSH key access.

Note: These tests require SSH access to a remote host with flubpub installed at /opt/flubpub/. Substitute your own user@host. If no remote is available, verify the CLI accepts the option and produces the expected SSH command structure.

4.1 Verify --remote Option Exists

Step: 
uv run flubpub --help
Expected: Output includes --remote TEXT SSH remote (e.g. root@host). Bypasses HTTP API.

4.2 Remote Push (HTML)

Step: 
echo "<p>Pushed via SSH</p>" > /tmp/ssh-test.html
uv run flubpub --remote root@danielwymark.com push /tmp/ssh-test.html --title "SSH Test" --slug ssh-test
Expected: SCP copies the file, SSH runs flubpub push on the remote. Output shows Published: SSH Test and the URL.

4.3 Remote List

Step: 
uv run flubpub --remote root@danielwymark.com list
Expected: Shows the page listing from the remote server, including "ssh-test".

4.4 Remote Get

Step: 
uv run flubpub --remote root@danielwymark.com get ssh-test
Expected: Shows page details from the remote server.

4.5 Remote Revise

Step: 
echo "<p>Revised via SSH</p>" > /tmp/ssh-test-v2.html
uv run flubpub --remote root@danielwymark.com revise ssh-test /tmp/ssh-test-v2.html --title "SSH Test Revised"
Expected: Revised: SSH Test Revised

4.6 Remote Push with Theme and Color Scheme

Step: 
uv run flubpub --remote root@danielwymark.com push /tmp/ssh-test.html --title "SSH Themed" --slug ssh-themed --theme geocities --color-scheme terminal
Expected: Page published on remote with geocities layout and terminal color scheme.

4.7 Remote Push Markdown with Local Refs

Step: Using the test files from Feature 1 setup:
cd /tmp/flubpub-img-test
uv run --project ~/projects/flubpub flubpub --remote root@danielwymark.com push album.md --title "Remote Album"
Expected: SCP copies album.md, main-photo.png, gallery.md, and sub-photo.png to the remote. The remote flubpub push handles the rest.

4.8 Remote Delete

Step: 
uv run flubpub --remote root@danielwymark.com delete ssh-test
uv run flubpub --remote root@danielwymark.com delete ssh-themed
Expected: Deleted: ssh-test and Deleted: ssh-themed

4.9 Remote with Invalid Host

Step: 
uv run flubpub --remote nobody@nonexistent.invalid list
Expected: SSH error: followed by connection failure message.

5. Cleanup

After testing, clean up the local test pages:

for slug in photo-album gallery cs-hacker-default cs-hacker-midnight \
            cs-geo-terminal cs-acad-starfield bad-scheme; do
  uv run flubpub delete "$slug" 2>/dev/null
done
rm -rf /tmp/flubpub-img-test /tmp/cs-test.html /tmp/cs-test-v2.html /tmp/ssh-test.html /tmp/ssh-test-v2.html
